## CRITICAL BUGS (3)
## =================================

### 1. House Reviews - Wrong URL
File: frontend/js/house-detail.js
Issue: Fetches /api/houses/:id/reviews which does not exist
Backend route is /api/reviews/:listingType/:listingId
Fix:
  const res = await fetch(${API_BASE_URL}/api/reviews/house/);

### 2. Admin JS Does Not Use config.js
Files: frontend/admin/js/reviews.js, faq-manager.js, contact-messages.js,
       site-settings.js, support-settings.js
Issue: Hardcoded URL - will not auto-detect localhost/LAN
Missing: <script src="../js/config.js"></script> in admin HTMLs
Fix: Add config.js script tag before each admin JS, remove hardcoded URL

### 3. Booking Email Says Confirmed But Status Is pending
File: backend/controllers/bookingController.js + emailTemplates.js
Issue: Email says "Your booking is confirmed!" but actual status is pending
Frontend hacks around it in my-bookings.js
Real fix: Change email to "Booking request received"

## SECURITY ISSUES (6)
## =================================

### 4. No Rate Limit on Public Booking
Route: /api/bookings POST
Issue: No rate limit - easy DoS/abuse
Fix: Add publicWriteLimiter like contact/subscribe routes do

### 5. No Auth on getOne House/Car
File: backend/controllers/houseController.js, carController.js
Issue: Anyone can fetch any listing including pending/rejected
Fix: Add check for non-approved listings unless owner/admin

### 6. Public Reviews Can Be Spammed
File: backend/controllers/reviewController.js
Issue: No rate limit, no check that user actually booked the listing
Fix: Add rate limit + validate user booked the listing

### 7. XSS in emailTemplates.js
File: backend/utils/emailTemplates.js
Issue: message from contact form inserted directly into HTML
Fix: Use escapeHtml(message) before interpolating

### 8. CORS LAN Regex - Could Be Too Permissive
File: backend/server.js
Issue: Any device on same LAN can hit the API
Note: Acceptable for dev, but ensure JWT_SECRET and MONGO_URI are strong

### 9. isBlocked Not Cached In JWT
File: backend/middleware/auth.js
Issue: If admin blocks user, access continues until JWT expires (7 days)
Fix: Shorter JWT expiry or re-check on critical actions

SECTION 2: SECURITY ISSUES (7)
============================================

SECURITY #1: No Rate Limit on Public Booking
Route: /api/bookings POST
Issue: No rate limit - easy DoS/abuse
Fix: Add publicWriteLimiter like contact/subscribe routes do

SECURITY #2: No Auth on getOne House/Car
Already covered in BUG #5

SECURITY #3: Public Reviews Can Be Spammed
File: backend/controllers/reviewController.js
Issue: No rate limit, no check that user actually booked the listing
Fix: Add rate limit + validate user booked the listing before reviewing

SECURITY #4: XSS in emailTemplates.js
File: backend/utils/emailTemplates.js
Issue: message from contact form inserted directly into HTML
Fix: Use escapeHtml(message) before interpolating

SECURITY #5: No CSRF Protection
Issue: JWT in httpOnly cookie is good, but state-changing requests vulnerable to CSRF
Fix: Add csurf or ensure same-site=strict for all cookies

SECURITY #6: bcrypt.hash(password, 10) Rounds Too Low
Files: backend/controllers/authController.js (signup, resetPassword)
Issue: 10 rounds is too low for 2024+ security standards
Fix: Increase to 12 rounds minimum

SECURITY #7: isBlocked Not Cached In JWT
File: backend/middleware/auth.js
Issue: requireAuth checks DB on every request (OK), but JWT only stores role
Problem: If admin blocks user, access continues until JWT expires (7 days)
Fix: Consider shorter JWT expiry or re-check on critical actions
